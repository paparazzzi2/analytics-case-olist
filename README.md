# Olist Analytics Case

Аналитический проект полного цикла на открытых данных бразильского маркетплейса Olist: требования, данные, процесс AS-IS, диагностика, сценарии TO-BE с оценкой эффекта.

> Учебный проект. Данные реальные (открытый датасет Olist, ~100 тыс. заказов за 2016–2018), заказчик и стейкхолдеры смоделированы.

## Результаты

- **6,8% заказов опаздывают**, в среднем на 10 дней, хотя обещанный срок вдвое длиннее фактического
- **Опоздание снижает оценку с 4,29 до 2,27**: опоздания — 6,7% заказов, но треть всех негативных отзывов
- **72% опозданий — этап перевозчика**, 28% — продавцы, нарушившие срок передачи
- **5 штатов** (MA, CE, BA, RJ, PA) дают 19% заказов и 35% опозданий
- **Повторные покупки (3,1%) почти не зависят от доставки**

Рекомендация: SLA для продавцов → A/B-тест уведомлений → пилот второго перевозчика в RJ. Цель: опоздания 6,8% → ≤ 5,5%. Подробно — [итоговый отчёт](docs/09_report.md).

## Структура

```
docs/   документация по этапам
sql/    схема БД, внешние ключи, запросы AS-IS, SQL-практика
src/    профилирование, загрузка в PostgreSQL, анализ процесса
data/   сырые данные (не в git, скачать с Kaggle)
```

## Как воспроизвести

1. Скачать [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce), CSV — в `data/raw/`
2. `python -m pip install -r requirements.txt`
3. Создать базу `olist`, выполнить `sql/01_create_tables.sql`, затем `python src/03_load_to_postgres.py` и `sql/02_add_foreign_keys.sql`
4. Анализ: `python src/04_process_analysis.py`
